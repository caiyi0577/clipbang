# iOS 端

## 当前状态

**v12.1：主流形态的拼音键盘（ccbroad）**。UI 与功能对齐微信 / 百度 / 讯飞 / 搜狗这类主流中文输入法，
纯 Swift / UIKit、零第三方依赖，词库随键盘扩展打包。

> **v12.1 / build 13 修复：键盘高度塌成一条线、完全出不来。**
> v12 重构三面板容器时漏掉了 `contentView` 的 required 高度下限。`UIInputViewController` 在
> `viewDidLoad` 阶段系统给的 view 高度是 0，单靠一条低优先级 `heightAnchor`，「高度 = 0」时
> 所有内部约束都能成立，系统封装高度约束就会赢，键盘被压平。v11 正是靠这条下限撑住的。
> 现在容器用 `UILayoutPriority(999)` 的目标高度 + `contentView >= 目标高度 - 46` 的 required
> 下限双保险；默认高度回到 v11 真机验证过的 320；`KeyboardPrefs.keyboardHeight` 对 App Group
> 里持久化的值做 260...400 钳制，任何异常小值都回落到 320；设置页切档位时两条约束同步更新。

### 界面

- 一条工具条：`设置 / 剪贴 / 粘贴 / 表情 / 更多 / 收起`，左侧 `ccbroad` 点一下回键盘。
- 候选栏：分词拼音串 + 清空、横滑候选、`▾` 展开「更多候选」宫格（最多 80 条）。
- 26 键按 iOS 系统键宽比例排布：键帽右上角上滑副标、按下放大预览、上滑直输副标、
  长按弹符号备选、长按删除连删。
- 四个页面：中文拼音 / 数字 + 中文标点 / 更多符号 / 表情（7 类 emoji + 颜文字）。
- 底行 `123 / 中·英 / 🌐 / 宽空格 / 回车`，回车跟随输入框显示「搜索 / 前往 / 发送 / 换行」。
- 深浅色跟随系统，也可在设置里固定；按键音、振动、候选字号可调；键盘高度三档 288 / 320 / 352 pt（默认 320）。

### 输入

- 全拼 / 简拼 / 混输、整词优先、连打续拼（选带 `›` 的候选后剩余拼音继续出词）。
- **710,935 条**「全拼 / 简拼 → 中文 + 词频」索引（34.8 万中文词 + 单字全部读音），
  PYD1 二进制 + `Data(..., .mappedIfSafe)` 内存映射 + 二分前缀查询；
  另带 4 万条全局高频表，保证单 / 双字母输入也出好词。
- 模糊音 9 组独立开关：`zh/z`、`ch/c`、`sh/s`、`n/l`、`r/l`、`f/h`、`in/ing`、`en/eng`、`an/ang`。
  声母在音节首替换、韵母在每个音节边界替换，连打时中间音节也能纠错。
- 用户调频：选过的词按次数加权，写进 App Group，可在设置里清空。
- 联想：上屏后用词库补全「以该词开头的更长词」，再补内置搭配表与通用虚词。
- 空格 / 换行上屏首候选，删除先退拼音再退正文；英文态直输、`⇧` 切大小写。
- 剪贴板记录库：键盘可见期 0.8 秒轮询自动采集，点条目插入；「粘贴」在用户手势上下文里读并入库。

### 暂未内置

双拼、滑行输入、语音、手写、云联想与皮肤商店：前两者需要独立输入码层，后几项涉及系统权限
与服务端，本版优先把拼音主链路和键盘交互做扎实。

数据来源与许可见 `Resources/Pinyin/SOURCES.txt`（jieba / pinyin-data / pypinyin，均为 MIT）。
生成脚本 `Tools/build_pinyin_dict.py`（Python 3 + pypinyin），CI 不运行它，仓库内提交的是已生成的 `.bin`。

签名描述文件必须带 `com.apple.security.application-groups`，当前使用的 group ID 是
`group.48bf5183109e5584.1`。没有这个权限时，主 App 和键盘各写各的沙盒，键盘列表会是空的。

剪贴板后台采集为什么改走键盘，见文末「已知结论」。

## 怎么取包

改动推到 `main` 后，Actions 会自动编译，产物同时出现在 Artifacts 和
`build-<运行号>` 这个 Release 里。

工作流里有一个 `probe` 小作业跑在 Linux 上：如果它成功而 `build` 被秒取消，
说明账号的 macOS runner 没额度或被限流，不是代码问题。

## 怎么装

1. 把 ipa 传到手机（文件传输助手、网盘都行）
2. 用 LC Sign 打开它
3. 选证书签名安装

装完检查键盘有没有一起进去：设置 › 通用 › 键盘 › 键盘 › 添加新键盘，看列表里有没有「ccbroad」。
记得打开「完全访问」，否则读不到剪贴板、共享记录库也是空的。

如果 App 能打开但键盘列表里没有，说明扩展没被签上，换个签名方式再试。

## 怎么验证

1. 任意输入框切到 ccbroad，敲 `nihao` → 候选栏出现「你好」，点一下上屏；
   上屏后候选栏不空，会显示联想词
2. 敲 `zg` 试简拼（中国 / 这个）、`chongqing` 试多音字（重庆）、
   `nihaoma` 试连打（选「你好 ›」后剩下的 `ma` 继续出候选）
3. 手指从 `q` 往上滑 → 直接输入 `1`；长按 `q` → 弹出备选条，左右滑动选；
   按住 `⌫` → 连续删除
4. 点候选栏 `▾` 或工具条「更多」→ 更多候选宫格；点「表情」→ emoji / 颜文字
5. 「设置」里打开 `zh ↔ z`，再敲 `zongguo` 应出现「中国」；
   同一个词多选几次，排序会明显往前
6. 「剪贴」里保持键盘可见、连续复制几段文字，应逐条出现，点任一条插入输入框
7. 设置页「关于」显示「内置拼音词库 710935条」；若显示「词库缺失」，
   说明两个 `.bin` 没被打包进 `.appex`
8. 键盘弹出后应能看到完整四行键帽和候选栏（标准档 320pt）；设置页把「高度」在
   矮 / 标准 / 高 之间切换，键盘应即时变高变矮，不会塌成一条线（v12.1 修复项）

## 已知结论

静音音频保活在 iOS 27 有效，后台轮询与进程内通知都能察觉剪贴板变化；
Darwin 跨进程通知已失效。App Group 已确认对主 App 与键盘都生效。

真机结论：把「从其他 App 粘贴」设为「允许」只消掉弹窗；后台依然被完全屏蔽
（`changeCount` 报 0、`items=0`、`string`/`data` 全 nil），只有切回前台才读得到
当前那一条。剪贴板是单槽，中间复制的内容在被覆盖时永久丢失，所以会出现
「复制三四条只存一条」。

攻坚版结果（已定论）：`MonitorProbe` 在通知回调里同步立即读，真机 10 次采集事件中
后台 9 次全部「通道=全断」，只有切回前台那 1 次读到内容。第一条后台通知甚至
`items=1`（能看见有条目），但 `string` / `data` 仍被拒——说明是授权层拒绝，
与读取时机无关，再快也没用。Objective-C 反射列出 `PBServerConnection` 共 29 个方法，
其中有 `preauthorizePasteForAuditToken:` 与 `requestPatternDetections...needValues:`
等预授权 / 带值接口，属私有 API 逆向范畴，本项目不再投入。

**结论：iOS 27 上「后台自动攒剪贴板历史」做不出来。** 剪贴板单槽 + 后台内容层
被完全拒绝，中间复制的内容在被覆盖时永久丢失。iOS 端保留当前形态
（键盘插入最近一条），不再为自动采集发版。Android 端不受此限制。
