# 移植契约

这份文档定义两个平台共同遵守的部分。目的是让安卓版先跑起来的同时，不给 iOS 移植挖坑。

写代码前先读，改接口前先改这里。

---

## 一、分层边界

代码分三层，只有第二层是两端共享的。

**第一层 · 平台实现层**：输入法服务、剪贴板读取、文字测量、渲染、存储。两端各写各的，不追求代码复用，只追求行为一致。

**第二层 · 共享逻辑层**：分词规则、词块布局算法、选中与状态转换、数据模型。这一层不许出现任何平台类型，安卓侧写纯 Kotlin，iOS 侧写纯 Swift，逻辑一一对应，两侧的单元测试用例要能互换。

**第三层 · 契约层**：本文档。平台差异、视觉参数、数据结构都记在这里，两端从这里取值。

判断一段代码该放哪层，只有一个问题：**它有没有 import 平台的东西**。有就进第一层，没有就进第二层。

---

## 二、数据模型

### 剪贴记录 ClipRecord

| 字段 | 类型 | 说明 |
|---|---|---|
| id | 字符串 | 全局唯一，两端都用 UUID，方便将来跨设备同步 |
| text | 字符串 | 原文，不做任何清洗 |
| kind | 枚举 | 文本／链接／号码／邮箱／色值／代码，决定卡片上显示什么图标 |
| createdAt | 长整型 | 毫秒时间戳 |
| pinned | 布尔 | 是否置顶 |
| sourceApp | 字符串可空 | 来源应用标识，仅用于展示，两端取值不同 |
| tokenCount | 整数 | 预先算好的词块数量，避免每次打开都重算 |

### 词块 Token

| 字段 | 类型 | 说明 |
|---|---|---|
| text | 字符串 | 块的文本 |
| start | 整数 | 在原文中的起始位置（按字符计，不按字节） |
| end | 整数 | 结束位置，不含 |
| kind | 枚举 | 词／数字／标点／表情／链接／空白 |
| selectable | 布尔 | 标点和空白不可选 |

`end - start` 必须等于 `text` 的字符长度，两端都要有断言校验。

### 存储

两端都用 SQLite，表名和字段名保持一致。安卓侧用原生 SQLiteOpenHelper（不引 Room，避免注解处理器拖构建），iOS 侧用 SQLite.swift，迁移版本号同步维护。

**保留规则，两端必须一致：**

| 项 | 值 | 说明 |
|---|---|---|
| 最多条数 | 99 | 超了删最老的 |
| 保留时长 | 14 天 | 超期自动清 |
| 单条上限 | 20000 字符 | 超了截断 |
| 置顶 | 不受上面三条限制 | 永不自动清理 |
| 去重 | 按全文查重 | 命中则刷新时间并提到最前，不新增 |

清理时机：每次写入后顺带清理一次；进程启动时再全表清一次。

敏感内容：带系统敏感标记的剪贴内容不记录，连内存都不进。安卓从 13 开始可以读这个标记，iOS 没有对应机制，需要自己判断（短文本加高熵字符组合）。

## 三、分词规则

分词分两步：先按规则硬切，切不开的再交给平台分词器。

顺序不能变，规则按下面的优先级依次匹配，命中即停。

| 序 | 规则 | 处理 | 可选中 |
|---|---|---|---|
| 1 | 换行符 | 硬边界，同时产生视觉换行 | 否 |
| 2 | 网址 | 以 http、https、ftp、www. 开头，或形如域名加路径 | 是 |
| 3 | 邮箱 | 含 @ 且两侧符合邮箱形态 | 是 |
| 4 | 长数字串 | 连续数字不少于 6 位，含内部连字符（电话、单号、身份证） | 是 |
| 5 | 数字加单位 | 数字紧跟字母或百分号（100km、3.5%、2026年） | 是 |
| 6 | 英文单词 | 连续拉丁字母，允许内部连字符和撇号 | 是 |
| 7 | 表情符号 | 整段表情序列算一块，含组合序列 | 是 |
| 8 | 中文标点 | 全角标点、各类引号括号 | 否 |
| 9 | 连续空白 | 折叠成一个块 | 否 |
| 10 | 中文 | 交给平台分词器 | 是 |

中文走平台分词器之后，还要过一遍合并规则：

- 单字块如果左右邻块也是单字，且三者都不在虚词表里，尝试合并
- 虚词表单独维护，两端共用同一份词表
- 数字开头的块如果紧跟量词，合并

没有命中任何规则的字符，按单字成块，保证不丢字。

### 限制

- 单条记录最多 500 块，超出部分截断，并在界面上标记
- 单块最长 200 字符，超长块在最近的标点处二次切分
- 空文本、纯空白文本不产生词块

## 四、布局算法

### 输入输出

```
输入
  blocks        每个块的宽和高，由平台层测量后传入
  containerWidth 容器可用宽度
  itemSpacing   块与块的水平间距
  lineSpacing   行与行之间的间距

输出
  positions     每个块左上角坐标
  totalHeight   排完之后的总高度
```

算法本身不测量文字，不读字体，不碰绘制。它只做一件事：拿到一串宽高，算出坐标。

### 排布规则

第一版用贪心换行：从左往右塞，塞不下就换行，行内左对齐。

硬边界（换行符产生的边界）必须强制换行，不能被合并到同一行。

后续如果要更好看的行宽分布，再换成全局最优断行，接口不变。

## 五、状态机

三个状态，转换条件写死，两端不许各加各的。

**列表态**：显示最近的记录，每条一行摘要。

**炸开态**：某条记录被炸成词块，铺满整个面板区域。

**选中态**：炸开态里已经选中至少一个块。

| 从 | 事件 | 到 |
|---|---|---|
| 列表态 | 长按某条记录 | 炸开态，目标为该条 |
| 列表态 | 点击某条记录 | 插入整条，回字母键盘 |
| 炸开态 | 点击可选块 | 选中态 |
| 炸开态 | 点标题栏返回 | 列表态 |
| 选中态 | 点击已选块 | 取消该块；若全部取消则回炸开态 |
| 选中态 | 点标题栏返回 | 列表态 |
| 选中态 | 点插入按钮 | 按原文顺序拼接已选块，插入后回字母键盘 |

插入动作只有两个出口：插入整条，或插入选中的块。没有第三种。

**关于点空白退出**：原设计是点空白回列表，实测在 Compose 里与词块点击、插入按钮抢手势，点击会被外层拦截。安卓侧改为只认标题栏返回，iOS 侧同样处理，避免两端行为不一致。

多选拼接时，被跳过的不可选块（标点、空白）如何处理：如果两个选中块在原文中相邻且中间只隔标点，把标点带上；否则用空格连接。这条规则两端必须一致。

## 六、平台能力差异

这张表决定了哪些功能能做、哪些一开始就不该设计。

| 能力 | 安卓 | iOS | 统一策略 |
|---|---|---|---|
| 输入法常驻 | 是，设为默认后常驻 | 否，只在键盘弹出时存活 | 采集端不依赖常驻，两端都走"面板打开时补录" |
| 剪贴板变化通知 | 设成默认输入法时可实时收到 | 没有任何通知 | 安卓侧做实时入库，iOS 侧只能靠面板打开时补录，两端记录条数会不同，属于预期差异 |
| 剪贴板读取 | 前台可读，后台受限 | 每次读可能触发授权弹窗 | 只在面板显示时读一次，不轮询 |
| 密码输入框 | 部分场景不弹自定义键盘 | 强制切回系统键盘 | 两端都拿不到，不设计相关功能 |
| 键盘高度 | 可自定义 | 受系统约束 | 高度作为常量管理，不放布局里算 |
| 中文分词 | 系统无，需自带引擎 | 系统有，质量中等 | 分词器做成可替换实现，规则层不变 |
| 后台存活 | 输入法进程常驻 | 不可 | 跨设备同步只能靠主动拉取，不靠推送 |
| 网络 | 自由 | 需完全访问权限 | 同步功能一律手动开关 |

**由此推出的产品边界**：不做"复制即记录"的实时采集，不做后台自动同步，不做密码框相关的任何能力。这些在 iOS 上做不到，安卓上做了就是白做。

## 七、视觉参数

数值来源统一，两端各写一份实现，不许自行微调。

| 用途 | 值 |
|---|---|
| 锤子红标题栏 | 上 #cd3f3a，下 #c83530，底边 #b7241f |
| 主操作蓝 | 上 #5b87eb，下 #5883eb，描边 #3f68e2，按下 #4772e6 |
| 页面底色 | #f5f5f5 |
| 卡片底色 | #ffffff |
| 分隔线 | #f2f2f2 |
| 描边 | #e2e2e2 / #eeeeee |
| 正文 | #333333 |
| 副标题 | #7f7f7f / #9d9d9d |
| 禁用 | #bababa |

间距基数是 6，只用 6、12、18、24、30、36 这几档。

圆角不超过 3，除了圆形按钮。

拟物细节三条：渐变只在同色系内做 2 到 5 个百分点的明度差；描边用 0.5 到 0.8 像素，颜色只比背景深一点点；凸起元素往下投 1 到 4 像素的短影，凹陷元素用内阴影。

## 八、命名

代码里的名字用"测什么"而不是"用什么实现"。分词器叫 `Segmenter` 不叫 `JiebaSegmenter`，安卓的实现类叫 `AndroidSegmenter`，iOS 的叫 `AppleSegmenter`。

命名里不许出现平台名，除非它是那个平台的实现类。
